# v0.11.0 release acceptance / security audit

Scope: **macOS arm64 non-OAuth real-client interoperability** remains the stable adapter scope. The CLI may attempt isolated interactive OAuth, but OAuth is *not* promoted to a stable or universally supported path in this v0.11.0 release. This is a pre-v1 release; the v1 stable-contract audit remains #193.

## Changes from v0.10.0

- `test --expect-tool NAME` (repeatable) / `--expect-tool-count N`: opt-in directly observed expected-name/count assertion; status `unknown` where actual name inventory is unobservable. Core `reach/auth/init/tools` PASS is unchanged (#197).
- `test --timeout 1s..10m` and `suite run --timeout`: bounded real-client execution and explicitly bounded suite budget; default behavior is preserved (#198).
- `suite repeat --attempts 2..5 --timeout ...`: independent validated result sets per attempt with complete/unstable/non-PASS semantics; no implicit baseline promotion (#199).
- `test --tool-evidence <file>` and `tools compare`: private protected-path expectation evidence schema v1 and opt-in drift report, without serializing unrequested tool names or changing strict core live-result schemas (#200).
- `report suite ... --html ... [--ci-summary ...]`: static offline HTML and Markdown summary from validated suite regression evidence; no scripts, network assets, untrusted raw version strings, URLs, logs or credentials (#201).

## No-change public contracts

- No change to `test` without opt-in flags, the four core stage meanings, legacy JSON array, exit code meanings, or strict portable live-result v1/v2, suite manifest v1, baseline v1.
- Fixture-only protocol observations are not promoted to real-client PASS. Absent/ambiguous named inventory is always `unknown`.
- `--tool-evidence` persists **only explicit expected names and counts** as separate operator-approved evidence. Unlisted tool swaps with unchanged count are deliberately undetectable.
- Offline HTML is a derived, sanitized *presentation*, never a signed attestation or authoritative replacement for retained evidence.
- Real-client Windows/Linux native acceptance and direct Resources/Prompts capabilities are **v0.12+** scope, not part of this release.

## Tag and distribution

The release workflow validates tags are descendants of `main`, executes `go vet`, `go test`, `go test -race`, `govulncheck`, security contract gates, and native packaged smoke on macOS arm64/amd64, Linux amd64 and Windows amd64. It builds six archive variants (including Linux/Windows arm64), SHA-256 checksums and GitHub attestations, then publishes the GitHub Release only after successful native checks. The release must be inspected for tag SHA match, archived binaries/checksums and release status before declaring completion.

# mcp-interop v0.11.0

Release scope: macOS arm64 real-client **non-OAuth** core interoperability. Existing `reach/auth/init/tools` PASS, legacy CLI JSON, portable artifact schemas and suite/baseline contracts are preserved.

## Highlights

- **Named tool expectations**: `test --expect-tool ping --expect-tool-count 3` checks directly observed client tool inventories without treating core PASS as evidence of exact names.
- **Expected-tool drift**: opt-in `test --tool-evidence expected.json` and `tools compare old.json new.json --fail-on-drift`, with a separately versioned private evidence format that stores only names the operator specified.
- **Timeouts and repeat runs**: `test --timeout 45s`, `suite run --timeout 2m` and `suite repeat --attempts 3 --timeout 45s`, preserving every attempt and classifying unstable results instead of accepting the last success.
- **Offline HTML and CI reporting**: `report suite baseline attempt-1 attempt-2 --html review.html --ci-summary summary.md --fail-on-regression` from validated suite evidence, with CSP, no remote assets or scripts, and private output files.
- **Release hygiene**: Go 1.26.9 security toolchain, cross-platform CI, timeout/SIGINT cleanup acceptance (including interrupted `suite repeat`) and targeted local OAuth fixtures for Codex/Cursor.

## Support and security boundaries

- Actual direct tool-name evidence is available in the Codex adapter; Cursor and Antigravity may return `unknown` for named-tool checks. Unlisted names are not serialized or diffed; an unlisted swap with unchanged count is not detectable.
- Interactive OAuth is experimental/outside the advertised stable adapter scope. Codex and Cursor passed controlled fixture acceptance; **Antigravity's Safari-backed current-main OAuth acceptance remains unverified** (#168) and must not be presented as stable.
- Windows/Linux real-client adapter compatibility has not been established merely because packaged binaries pass their native smoke tests.
- Release artifacts are evidence, not cryptographic attestation of the underlying real client. Do not place credentials, URL secrets or private tool names in expected-name CLI flags or deployment labels.
